# Source References

One file per source we drew requirements from: a Fathom recording, client document, email thread, RFP, consultant notes, or Hero's own guidance.

- **ID prefix:** SRC
- **Example:** `SRC-001-kickoff-call.md`
- **Links upstream to:** nothing (sources are the start of the chain)

The file holds the name, type, and a link to where the original lives (Fathom, WorkDrive, Gmail). Originals stay where they are; extracted text goes in `raw/`.

## Source types

| Type | What it is |
|---|---|
| meeting | A recorded call or meeting, usually a Fathom transcript |
| document | A client document: process docs, spreadsheets, existing system notes |
| email | An email thread |
| notes | Observations from a Hero consultant |
| guidance | Hero's direction on approach: which app, how something should be built, what's in or out of scope. Includes an approved solution outline. |
| rfp | A request for proposal |
| other | Anything else |

When sources disagree, client sources are authoritative on **what the business needs**, and `guidance` is authoritative on **how we'll approach it**. Conflicts on the "what" get flagged, never silently resolved.
